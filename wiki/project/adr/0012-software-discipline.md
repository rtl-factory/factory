# Software is a discipline: what runs on the design's CPU is `sw`, what runs on the host is a script

Code and data that run on a design's own CPU (C and assembly sources, firmware and runtimes, linker scripts and the target build setup, ROM and data images built for the design) are the `sw` discipline, `src/<project>/sw/<name>/`, documented at `wiki/src/<project>/sw/<name>/`. ADR 0011 left `sw/` as an extra project folder beside the disciplines; nand2doom (a C runtime, a Doom port, a linker script, pinned third-party inputs) made it as large as any discipline, and the open question was whether its C code and build setup belong in `scripts/`. They do not: the line is which CPU a file runs on, so a host program that compiles, assembles, loads or drives that software (nand2doom's `n2d_doom.py`, nand2mario's assembler) stays a script even when it exists only for it. `cfg/` stays a project folder, not a discipline. nand2mario already followed this, with its Game Boy programs in `src/nand2mario/sw/`, so nothing moves.
