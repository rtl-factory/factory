# A first mate orchestrates crewmates; captains talk only to the first mate

Humans are captains. Each captain works through one agent, the first mate, which dispatches crewmates, gives each one issue on its own worktree and issue branch, supervises them, and lands their work: straight from an issue branch into `main`, or through an epic branch when the issues must land together. This fits the issue and epic workflow (ADR 0003, ADR 0004): an epic is the first mate's natural unit of orchestration, and its sub-issues are the crewmates' units of work. We adopt the roles and principles, written as the first-mate BKM, from [kunchenguid/firstmate](https://github.com/kunchenguid/firstmate) (MIT) rather than its distro, so it fits a team on GitHub instead of one operator on one machine. The alternative, captains juggling many agent sessions directly, does not scale past a few parallel issues. The one exception is competing candidates: when one attempt would lock in the wrong shape, the first mate may dispatch several candidate crewmates on the same issue, each on a scratch branch; only the chosen one becomes the issue branch, so one issue still lands through one issue branch and one pull request.
