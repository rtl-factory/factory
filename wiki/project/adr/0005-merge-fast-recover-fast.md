# Merge fast, recover fast: cumulative regression levels

Pull requests into `main` gate only on L1, a minimal check that includes L0, the fastest checks, which anyone can also run on demand. L1 runs again after the merge, and slower regression runs on `main` on a schedule: L2 hourly, L3 every 6 hours, L4 nightly, each level including all lower ones. We accept that `main` can be broken for up to a few hours in exchange for fast merges, because the scheduled levels catch failures soon and the fix goes in through an issue at once. The alternative, running long regressions before every merge, would make each pull request wait hours.
