# Full send by default; a captain opts an issue out

Agents act under their captain's account, and GitHub never lets an author approve their own pull request, so approval is a step in the flow, not a GitHub review: the rulesets require zero GitHub approvals. By default (full send) the reviewer crewmate's pass and a green L1 are enough, and the first mate merges on its own. A captain marks an issue `authority:needs-captain` when a human must explicitly say the pull request is ready; the first mate records that as a pull request comment before merging. Pull requests that change the factory's controls (BKMs, skills, `AGENTS.md`, glossary, ADRs, `.github/`) always need captain. GitHub does not enforce either mode; the Merging section of the flow BKM does, and we accept trusting agents to follow it. This replaces an earlier draft in which a captain's approval was the default and a `full-send` label was the exception: most work is done by agents, so autonomy is the common case and the captain spends attention only where they asked to.
