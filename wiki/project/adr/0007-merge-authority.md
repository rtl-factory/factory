# Approval is a step in the flow, not a GitHub review

Agents act under their captain's account, and GitHub never lets an author approve their own pull request. Rather than give agents a separate bot identity or make captains approve each other's work, we require zero GitHub approvals and make approval a step in the flow: a reviewer crewmate passes the pull request, then the captain gives the go-ahead, which the first mate records as a pull request comment. An issue labelled `full-send` skips the captain's go-ahead. GitHub enforces the pull request, the `issue-link` check and L1; it does not enforce approval, so the flow BKM does, and we accept trusting agents to follow it.
