# Documents live in the wiki, mirroring the code tree; tools are repo tools or project tools

Code lives in the source tree and every document about it (block specs and plans, tool PRDs and specs) lives in `wiki/` at the path that mirrors the code, so `tools/sim/` is documented in `wiki/tools/sim/` and `src/common/tools/jtag/` in `wiki/src/common/tools/jtag/`. A tool any project can use unchanged is a repo tool under `tools/`; a tool bound to one project, or to a block of `common`, is a project tool under `src/<project>/tools/`. This replaces the layout of issue #56, which kept each tool's `prd.md` and `spec.md` beside its code and published them through a site-build hook: one rule now places every document, the wiki is the single place to read and edit them, and project tools, which that layout did not cover, get their documents too. We accept that a tool's code and its documents sit in two folders, and keep them in step by changing both in the same pull request (`wiki/bkm/workflow/repo-layout.md`).

_The "repo tool" and "project tool" names above are replaced by [ADR 0011](0011-disciplines-and-scripts.md): only `tools/` holds tools, and code bound to a project is a script in `src/<project>/scripts/`. The mirror rule stands._
