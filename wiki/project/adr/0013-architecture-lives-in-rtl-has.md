# No architecture discipline: a project's architecture is its rtl HAS, and each discipline has standard documents

The disciplines are `rtl`, `dv`, `fv`, `fpga`, `scripts` and `sw`; the `arch` discipline of ADR 0011 is removed. A project's architecture is written as the HAS (high-level architecture specification) of its `rtl` discipline, `wiki/src/<project>/rtl/has.md`, and each block's design as its MAS (micro-architecture specification), `wiki/src/<project>/rtl/<block>/mas.md`; verification has a DV plan per block (`dv-plan.md`), formal an FV plan (`fv-plan.md`), each board a board spec (`board-spec.md`), and scripts and software a PRD and a spec (`wiki/bkm/layout.md`). We folded `arch` into `rtl` because nothing concrete argued for keeping it: no project had any `arch` code or document, the captain's list of disciplines and documents put the HAS under RTL, the one kind of code ADR 0011 imagined there (a behavioural model of a block) is a DV reference model or a throwaway prototype in practice, both already placed by the DV and planning BKMs, and an architecture kept apart from the RTL it shapes is a second spec that drifts. The architecture BKM moves with it, from `wiki/bkm/arch/` to `wiki/bkm/rtl/`. If a project later needs architecture code that is neither a reference model nor RTL (a performance model run as its own deliverable, say), reopen this ADR rather than placing it in `rtl` or `dv` by force.
