# Requirements

Product requirements documents (PRDs): what a piece of hardware must do, for whom, and how we will know it does, before any block is specified. One file per product or major feature, named `<product>.md`.

!!! note "Placeholder"
    No requirements documents yet. The first one will be written from an alignment session (`wiki/bkm/design/grilling.md`) and split into issues (`wiki/bkm/workflow/issues.md`).

A requirements document should hold:

- **Problem**: who needs this and why.
- **Requirements**: numbered, each one testable (performance, area, power, interfaces, standards to comply with).
- **Out of scope**: what it deliberately does not do.
- **Acceptance**: how each requirement will be verified.
- **Blocks**: the blocks that implement it, linking to their specs under [Blocks](../src/README.md).
